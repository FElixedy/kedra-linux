# kedra-keyring

The Kedra Linux PGP trust root, packaged the way Arch packages keyrings.

## What it contains

| File | Purpose |
|---|---|
| `/usr/share/pacman/keyrings/kedra.gpg` | public keys: the Kedra master key and the packager key(s) it certifies |
| `/usr/share/pacman/keyrings/kedra-trusted` | `<master-fingerprint>:5:` — the trust anchor and its ownertrust |
| `/usr/share/pacman/keyrings/kedra-revoked` | fingerprints to disable on update (currently empty) |

The install scriptlet runs `pacman-key --populate kedra`, chrooted into the
installation root, which is what makes the package usable from pacstrap and
Calamares against a target that is not `/`.

**Public key material only.** No private key is in this repository or in the
built package.

## Additive, never a replacement

`kedra-keyring` has no `conflicts`, `provides` or `replaces`. A Kedra system
carries all three keyrings:

```
archlinux-keyring + cachyos-keyring + kedra-keyring
```

Kedra does not replace or fork upstream keyrings, and packages from `[core]`,
`[extra]` and the CachyOS repositories keep verifying against their own keys.

## The keys currently shipped are DEVELOPMENT ONLY

They are generated by `kedra-repo/bin/kedra-dev-keys-init`, carry
`DEVELOPMENT ONLY - NOT A PRODUCTION KEDRA IDENTITY` in their user IDs, and use
the reserved `@kedra.invalid` domain. They exist so the repository and signing
pipeline can be validated before production signing infrastructure exists.

Do not treat anything signed by them as trustworthy for users. See
`kedra-repo/docs/signing.md` for how they are replaced, including revoking them
via `kedra-revoked` in the same release that introduces the production keys.

## Regenerating

```sh
../kedra-repo/bin/kedra-dev-keys-init      # rewrites kedra.gpg + kedra-trusted
makepkg --printsrcinfo > .SRCINFO
```

`sha256sums` are `SKIP` by design: the keyring is regenerated whenever keys are
added, rotated or revoked, so pinning them would only mean editing two files
instead of one. Integrity of the shipped keyring comes from the signature on the
package itself.
